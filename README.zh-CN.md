# Time Mirror · 时光镜像

Time Mirror 是一个全栈 Web 应用：用父母投喂的回忆，为孩子构建一个**数字分身**。每一条回忆变成一粒光点，
记忆越多，分身轮廓越清晰；与它对话时，答案只来自这些回忆，不来自编造。

**在线演示（静态页面，浏览器直接打开）：**<https://voskamp099.github.io/time-mirror-demo/>

本仓库 `demo/` 是产品主循环（投喂 → 成长 → 对话）的自包含静态演示：对话回复由本地检索与模板合成，
因此不依赖服务器也不调用大模型；下面的完整应用则用大模型流式返回回答。

演示发布在两个路径上，内容是同一个文件：笔记站上的 `/time-mirror-demo/`（规范路径），以及本仓库自带
Pages 分支上的 `/time-mirror/`。源文件是 `demo/index.html`；笔记站里另有一份副本
`time-mirror-demo/index.html`，改动演示时两处要一起改。

## 产品

| 页面 | 做什么 |
| --- | --- |
| 开机引导 | 创建分身：家长姓名、孩子信息、生日、孪生形象 |
| 投喂回忆 | 写入回忆：文字、五种时间标签（多选）、情绪、场景、自定义标签；桌面端支持 Excel 批量导入 |
| 回忆面板 | 光点粒子头像、记忆光球、时间线、镜子碎片卡片、「那年今日」 |
| 成长界面 | 气质九维雷达、智能八维雷达、发展阶段时间线、五种时间分布、情绪模式、可点击溯源的价值种子 |
| AI 对话 | 与数字分身流式对话，家长视角（第三人称）与孩子视角（第二人称）可切换 |

## Agent 的部分

有意思的不是界面，而是回答怎么被"钉"在真实记忆上：

1. **记忆结构化** —— 每条回忆归一成 `{日期、内容、时间类型、情绪、场景、标签}`；
2. **检索** —— 命中的回忆作为 `memoryContext` 注入系统提示词；
3. **人格提示词** —— 规定只能依据真实细节作答、保持家长或孩子的口吻，证据不足时必须承认不了解；
4. **流式返回** —— API 路由以 SSE 逐字返回，回复是边生成边出现的。

提示词的规则刻意保守，因为"孩子的数字分身"最大的失败模式，是对一个真实的孩子编出自信的细节：

- 只用已有记忆回答，不编故事；
- 记忆覆盖不到时直说「这段我还不够了解你」；
- 引用具体细节，而不是泛泛而谈；
- 不说教，不给标准答案。

## 技术栈

- **框架**：Next.js 16（App Router）、React 19、TypeScript 5
- **界面**：shadcn/ui（Radix UI）、Tailwind CSS 4、暖色「晨光」主题、Canvas 粒子系统
- **后端**：`src/app/api/chat/route.ts`，模型流式输出转成 SSE
- **存储**：Drizzle ORM + PostgreSQL、Supabase 客户端、S3 兼容对象存储放媒体
- **数据导入**：投喂页的 Excel 批量导入用 SheetJS

## 怎么构建出来的

这是一次 AI Native 的开发：产品设定、视觉语言与实现由 AI 编码工具（AI 智能体工作区 + 终端编码 agent）
产出并迭代，设计决策留在 `DESIGN.md` 与 `AGENTS.md`，让后续每次改动都遵守同一套规则——暖色系、圆角、
不用冷蓝、动画要慢、回忆不该用数据表格呈现。

## 跑完整应用

项目是在 AI 智能体工作区里创建的，依赖它自己的平台工具链：

```bash
pnpm install
coze dev        # 或 bash scripts/dev.sh
```

模型调用走工作区自己的客户端 SDK，凭证由环境注入，仓库里不存任何密钥。生产路径是 `scripts/build.sh`
加 `scripts/start.sh`。只想看产品行为的话，直接开静态演示即可，不需要任何依赖。

## 目录

```

DESIGN.md           视觉语言与产品规则
AGENTS.md           页面地图、技术栈与结构说明
```
